1 Portal Overview — Who Does What

The Superclass Portal is an academic operations platform with four distinct roles. Each role has its own dashboard and access level. No role can access another's data unless explicitly shared.

🛡 Admin
/admin
Sets up the entire system — centres, classrooms, programs, subjects, syllabus (GTT), and all user accounts. The foundation everything else is built on.
🎯 Central Team
/central
Runs day-to-day academics — creates batch schedules, builds planners, assigns topics to faculty, schedules tests, audits lectures. The primary operational role.
🏫 Branch Head
/branch
Manages their own centre — can edit batch schedules, view tests and calendar, handle attendance and results. Cannot create batches or touch planners.
👨‍🏫 Faculty
/faculty
Views their assigned lectures and confirms them after teaching. Can raise reschedule requests. Cannot modify any planner content — read + confirm only.

2 Admin Portal

The Admin portal is where the entire system's infrastructure is configured. Nothing else works until the admin sets up the foundation.

🏢 Centres & Classrooms

Each physical location is a Centre (e.g. Patna Superclass, Pitampura Superclass). Inside each centre are Classrooms / Halls (Room 1 · Study Space, Star Base, Idea Hub, etc.).

Each centre is assigned a Branch Head who manages that centre's day-to-day operations.

📚 Programs & Subjects

A Program is a course (CA Foundation, 11th Commerce, CLAT 2027, CUET, etc.). Each program has multiple Subjects (Accounts, Maths, Legal Reasoning, etc.).

🧠 Syllabus — GTT (Concept Tags)

This is the most important setup step. For each subject, Admin defines:

  • Chapters — e.g. "Sets, Relations & Functions", "Differentiation"
  • Topics within each chapter — e.g. "Product Rule", "Chain Rule"
📌
Why it matters: The entire planner, test chapter selection, bulk upload validation, and syllabus coverage % all rely on this GTT data. Chapter names must exactly match GTT when used anywhere else in the portal.

👥 Users

Admin creates all user accounts and assigns roles: Faculty (with subject specialties and centre), Central Team members, Branch Heads, Batch Managers, and Credentials for login.

📊 Audit Report

A dedicated report page showing batch-owner-wise lecture audit data with date-wise grids, summary stats, and CSV export capability.

3 Central Team Portal

The Central Team does the bulk of academic operations. The portal is divided into several workspaces accessible from the hub.

🗓 3.1 Batch Scheduler

Sets the weekly recurring timetable for each batch — which subject runs on which days, at what time, in which room, taught by which faculty.

1
Create a Batch Name, Program, Centre, Start Date, End Date. Also assign a Batch Manager (offline batch manager) and a Batch Owner (central team member responsible for auditing this batch).
2
Set Weekly Schedule For each subject: select days of the week, time slot, classroom, and faculty. Multiple date ranges are supported — e.g. Physics on Mon/Wed until Aug, then Mon/Tue/Thu from Sep.
3
Save The schedule is saved. Existing future lectures are updated with the new time/room automatically. New buffer slots are created for any new day slots added — these are used when adding extra classes later.
💡
Batch Owner vs Batch Manager: These are two different fields. Batch Manager = the person running the offline batch. Batch Owner = the Central Team member who owns audit responsibility for this batch.

📋 3.2 Batch Planner

A planner maps the full syllabus to specific dates — chapter by chapter, topic by topic. It is the academic backbone of a batch.

Three-step process

1
Create Planner — Build the Template Add chapters and topics from GTT. Assign dates. The system automatically snaps dates to valid class-days from the batch schedule. Buffer slots are included as empty placeholder rows for future flexibility.
2
Assign Planner — Link to a Batch Attach the planner to a batch. The system materialises all lectures — each lecture gets its exact date, start time, classroom, and faculty from the batch schedule. Overlap-free, always.
3
Send to Faculty — Week by Week Publish the schedule to faculty. Each faculty sees their upcoming lectures and confirms them after teaching. Past lectures are auto-confirmed. Publishing can be done week by week.

Edit Planner — Live Mode

Once a batch has a linked planner, select that batch in Edit Planner to enter Live Mode — editing goes directly to that batch's actual schedule.

View Mode What You See Best For
📅 Date View (default) All lectures in chronological order — today onwards Day-to-day tracking, quick status updates
📖 Chapter View Grouped by chapter within each subject tab Reviewing topic coverage, reordering

Status Flow for Each Lecture

Planned → confirmed by faculty → Confirmed → marked taught → Conducted

Adding Extra Classes (+Add Row)

When Central Team clicks + Add Row on a chapter, the next available buffer slot for that subject is converted into a real lecture. The date, time, and room are inherited from the buffer (which was created from the batch schedule).

⚠️
If "No buffer slots left" appears: Go to Batch Scheduler → open that batch's schedule → click Save (even without changes). New buffer slots will be automatically created for all schedule days. Then +Add Row will work again.

Rescheduling

When a lecture is moved to a later date, it lands on the next available buffer slot — the batch's end date never extends. Buffers absorb the shift.

📝 3.3 Test Scheduler

Schedule tests for one or multiple batches. Tests are confirmed immediately — no draft/send-to-faculty flow. Once scheduled, the test appears in everyone's calendar.

Scheduling a Single Test

1
Select Centre This filters the batch list to only that centre's batches.
2
Select Batch(es) Check one or multiple batches. Multiple batches must be from the same centre and same program.
3
Set Test Details Name, Date, Start Time, Duration, Type (Objective/Subjective/Mixed), Scope (Full Syllabus or Specific Chapters).
4
For Part Tests — Select Chapters from GTT Pick the subject, then select chapters from the GTT list. Each chapter shows what % of it has been taught so far — a helpful guide before scheduling.
5
Room + Invigilator → Schedule Test ✅ The system validates for clashes. If a class clashes, "Schedule & Shift Classes" appears — approve to shift the clashing lecture to a buffer slot.

Bulk Upload via CSV

Download the template, fill in multiple tests, and upload at once.

CSV Columns:

Centre Batch Multiple Batches Subject Test Name Date Time Duration Type Scope Chapters (GTT names) Room Invigilator Email

Highlighted columns are required. All others are optional or have defaults.

After upload, a preview table shows each row's status:

✅ Ready — No issues, will be imported as-is   ⚠ Will Shift — A class clashes; lectures will be shifted to buffers   ❌ Error — Validation failed; will be skipped

📌
GTT Chapter Validation: Chapter names in the CSV must exactly match the names defined in Admin → Syllabus (GTT). If a chapter name doesn't match, the row is flagged as an error.

Syllabus Coverage % (the 60% Gate)

Each upcoming test shows a syllabus coverage indicator — what percentage of the test's syllabus has been taught as of the test date. Below 60% shows a warning ⚠. This is informational — it does not block scheduling.

🔍 3.4 Daily Lecture Audit

Central Team's quality control tool. Each day, team members verify that scheduled lectures actually happened correctly.

Column What to Fill
Lecture Link YouTube or Drive URL of the recorded lecture
Topic ✓ Was the correct topic taught as per the planner?
Duration ✓ Was the full class duration completed?
PPT ✓ Was quality presentation material used?
Remarks Any observations, feedback, or issues

When you save, the status is set automatically:

✅ Audited All 3 boxes checked   🚩 Flagged Any box unchecked or partial   ⏳ Pending Nothing filled yet

Batch Owner Filter: If a Central Team member is assigned as Batch Owner for certain batches, their audit view automatically filters to show only those batches. Other team members see everything.

Stats at a Glance

The top strip shows: Today's classes · Today pending · Earlier pending (from Aug 19 onwards) · Total pending · Done today.

📅 3.5 Calendar (Schedule View)

A centre-wide day view showing every hall on a selected date. Three types of events are shown side by side:

Event Type Appearance Source
Class Solid color block with batch name Recurring weekly schedule (Batch Scheduler)
Planner Lecture Color block with thick left border + topic name Actual materialised planner entry
Test Black block with test name Scheduled test

No two events in the same hall at the same time — the system enforces this at every entry point.

🔄 3.6 Reschedule Requests

Faculty submit requests from their calendar. Central Team reviews and acts on them here.

Request Type What Happens on Approve
Reschedule That lecture moves to the faculty's requested slot; the planner updates automatically
Extra Class A new lecture is added at the requested slot
Prepone Chapter All lectures of that chapter are moved earlier in the schedule
Cancellation Lecture is cancelled; option to assign a substitute faculty
✅
All approvals are immediate: The planner updates in real-time when Central Team approves. Faculty sees the change in their calendar right away. No manual sync needed.

📈 3.7 Progress Tracking

Per-batch academic health dashboard showing:

  • Overall syllabus % covered vs planned end date
  • Buffer slots: total / used / remaining
  • Subject-wise breakdown — which subjects are on track, ahead, or behind
  • Warning if a subject will not finish by the batch end date

The Branch Head manages their assigned centre. They see only their own centre's data.

Feature What They Can Do
Batch Scheduler Edit the weekly schedule (time, room, day) for their centre's batches. Cannot create, delete, merge batches, or attach planners.
Tests View all scheduled tests for their centre
Calendar Day view for their centre — all halls, all events
Students Manage student records for their centre

5 Faculty Portal

Faculty has a simple, focused experience. They cannot modify any planner content — their role is to confirm lectures and raise requests when needed.

📋 My Planners

Shows all assigned lectures in date order, grouped by batch and chapter. For each lecture, faculty sees:

  • Date & Time — set by the schedule
  • Classroom — assigned room
  • Chapter & Topic — set by Central Team, read-only
📌
Faculty can ONLY Confirm. They cannot edit topics, chapters, dates, or any planner content. Central Team is the sole authority on what the planner contains.

Two confirm options:

  • Confirm — confirm one lecture at a time
  • Confirm All — confirm all pending lectures for a batch at once

📅 Calendar

A personal calendar view of all upcoming lectures and tests. Faculty can raise Reschedule Requests from here — click on a lecture to request a date/time change, extra class, or cancellation. Central Team reviews and approves/rejects.

6 The Buffer System — How Capacity Works

Buffers are the key mechanism that keeps batch schedules flexible without ever extending the batch end date.

🧩 What Is a Buffer?

A buffer slot is a reserved, empty class slot in the batch planner. It has a date, time, and room (inherited from the weekly schedule) but no topic, chapter, or faculty assignment yet. Think of it as a blank seat in the calendar.

📌 How Buffers Are Created

Buffers are automatically created when:

  • A planner is first assigned to a batch (extra slots are created beyond the actual lecture count)
  • Batch Scheduler is saved with a new day/slot — the system creates buffers for all future dates on that new slot

⚡ When Buffers Are Used (Consumed)

Action What Happens to Buffers
+Add Row in Edit Planner The nearest future buffer for that subject is converted into a real lecture
Reschedule (lecture moved forward) The lecture lands on the next available buffer date; batch end date stays unchanged
Test scheduled (class clash) Clashing class moves to buffer; test occupies its original slot

🔄 Replenishing Buffers

Problem: "+Add Row" shows "No buffer slots left" → Go to Batch Scheduler → Open the batch's schedule → Click Save (no changes needed) → New buffer slots are automatically created for all future schedule days → Return to Edit Planner — +Add Row now works ✓
✅
The batch end date NEVER moves. All shifts, extra classes, and test-priority moves are absorbed by buffer slots. If there are no buffers left, new capacity must be explicitly added through the Batch Scheduler.

7 End-to-End Workflows

📋 Full Planner Lifecycle

ADMIN └── Define subjects + GTT (chapters & topics) per program CENTRAL TEAM — Setup └── Batch Scheduler → Create batch + set weekly schedule (days/times/rooms/faculty) CENTRAL TEAM — Planner └── Create Planner → add chapters/topics from GTT, assign sequence └── Assign Planner to batch → system materialises all lectures with correct dates/times/rooms └── Send to Faculty (week by week or all at once) FACULTY └── View lectures in My Planners └── Confirm each lecture after teaching └── Raise reschedule request if needed CENTRAL TEAM — Ongoing └── Reschedule Requests: review → approve/reject └── Edit Planner (Live Mode): update topics, add rows, mark conducted └── Daily Audit: verify lecture quality each day └── Progress Tracking: monitor syllabus coverage

📝 Test Scheduling Lifecycle

CENTRAL TEAM └── Test Scheduler → New Test └── Select Centre → filter batches → select batch(es) └── Set date/time/duration/type/scope └── Part Test? → select subject → pick chapters from GTT └── Select room → optional invigilator └── "Schedule Test" → directly Confirmed ✅ ├── No clash: done immediately └── Class clash: "Schedule & Shift" → lectures shift to buffers → test confirmed EVERYONE └── Test appears in Calendar on the scheduled date └── Syllabus % shown (60% gate is informational only)

8 Common Scenarios

🔴 "Need to add an extra class for a chapter"
Central Team → Edit Planner → Select batch → Find the chapter → Click +Add Row. The next available buffer slot is converted into the new class. Save the planner.
🔴 "+Add Row says 'No buffer slots left'"
Central Team → Batch Scheduler → Open the batch → Save (no changes needed). New buffers are auto-created. Return to Edit Planner and try +Add Row again.
🟡 "Faculty can't make it — class needs to be moved"
Faculty → Calendar → Click the lecture → Submit Reschedule Request with preferred new slot. Central Team → Reschedule Requests → Review → Approve. Planner updates automatically.
🟡 "Test date clashes with a scheduled class"
During test creation, the system detects the clash and shows "Schedule & Shift Classes". Click it — the clashing lecture moves to a buffer slot, and the test is confirmed.
🔵 "Schedule same test for multiple batches at once"
Test Scheduler → Select Centre → Check multiple batches (same centre + program) → Fill test details → Schedule Test. All batches get the test linked.
🔵 "Upload 20 tests at once via CSV"
Test Scheduler → Bulk Upload → Download Template → Fill with Centre, Batch, Test Name, Date etc. → Upload → Review preview (Ready/Shift/Error) → Import All.
🟢 "Audit all today's lectures"
Daily Lecture Audit → Select today's date → Filter by Centre/Batch if needed → For each class: add lecture link, check the 3 boxes, add remarks → Save (auto-confirms as Audited or Flagged).
🟢 "Get weekly audit report for management"
Admin Portal → Audit Report → Set date range → View Summary (owner-wise grid) or Detail (all lectures) → Click Download CSV.

9 System Rules

These rules are enforced by the system — they cannot be bypassed.

🚫
Faculty cannot edit any planner content. They can only confirm lectures. Chapters, topics, dates, and times are set by Central Team only.
📅
Batch end date never extends. All lecture shifts (from reschedules or test priority) land on existing buffer slots within the batch's timeline.
🏢
No overlapping classes in the same room. The Batch Scheduler blocks any overlapping time slots in the same classroom.
📚
Chapter names must match GTT exactly. In bulk test upload and planner creation, chapter names are validated against the Admin-defined syllabus.
✅
Tests are confirmed immediately. There is no Draft → Send to Faculty → Confirm flow for tests. Schedule it — it's live.
🏫
Branch Heads see only their centre. All data access (batches, tests, calendar) is automatically scoped to their assigned centre(s).
🔄
Planner approvals are real-time. When Central Team approves a reschedule request, the planner updates immediately — no manual sync or refresh needed.
📊
Syllabus % is capped at 100%. Coverage is calculated per chapter (not globally), so common topic names across chapters don't inflate the percentage.
