The root is a Next.js App Router application whose `app/` directory is split into one top-level folder per portal (`admin`, `central`, `faculty`, `branch`, `batch-manager`) plus shared entry points (`login`, `auth/callback`, `choose-role`). Cross-cutting concerns live in `lib/` — `lib/supabase/client.ts` and `server.ts` expose Next.js-aware Supabase clients consumed by every portal page; `lib/auth.ts`, `lib/validation.ts`, and `lib/scheduling.ts` hold the shared domain logic reused across portals. All requests are funneled through `proxy.ts`, which uses `@supabase/ssr` to read cookies, checks `app_users.role`/`roles` against `PROTECTED_ROLE_PATHS`, and redirects users to their correct portal prefix. The `components/PortalShell.tsx` and per-portal `layout.tsx` files wrap each portal's UI with navigation and auth state. Data initialization lives under `scripts/` (seed SQL + CSV import helpers) and is invoked via npm scripts rather than at runtime.
